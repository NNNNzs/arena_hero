# Arena Hero 战术地图设计文档

## 1. 文档目的

本文档说明作战指挥中心中的战术地图如何把经过脱敏和限幅的态势投影为可交互的二维视图。它覆盖渲染、相机、图层、交互、性能与回放边界；策略决策、权威 `Turn` 和提交规则仍以 [Arena Hero Tactic 设计文档](arena-hero-tactic-design.md) 为准。

代码行为最终以 `arena_tactic/web/static/tactical-map.js`、`command-center.js`、`command-center.css` 和 `arena_tactic/dashboard.py` 为准。地图是观测与受限任务输入界面，不是游戏状态源，也不参与 Agent 的实时动作决策。

## 2. 定位与数据边界

地图展示指挥中心 `/api/dashboard` 提供的当前或已选回放帧。浏览器只消费已投影的 `current.map` 和同一帧的指挥中心实体摘要；它不读取运行状态文件原文，不接触 SDK `Turn`、控制器、API Key、Cookie、原始 UUID 或未批准字段。

| 主题 | 设计约束 |
| --- | --- |
| 可见性 | 只投影当前可见的己方、敌方、资源、障碍与 Beacon 坐标；历史位置不补绘为当前对象。 |
| 身份 | 实体以脱敏 alias 对齐地图与指挥中心；前端不需要、也不展示原始 UUID。 |
| 限幅 | 己方 Unit 最多 100（另含 Core）、敌方最多 100；资源、障碍各最多 200；已观测格最多 2,000。 |
| 数据路径 | `DashboardDataStore` 读取有界的脱敏回放尾部并做 allowlist 投影，地图再对该投影做格式校验与可见域裁剪。 |
| 失效语义 | 新帧是新的显示快照；实体消失时删除其地图模型、选中/追踪状态和 Pixi 显示对象，不能把旧帧实体当作当前实体。 |

这种边界与 Tactic 的权威状态原则一致：地图可帮助操作者理解“当前可见什么”，但不能从图上推断不可见敌人、资源存量或未来位置。

## 3. 渲染管线

### 3.1 主路径与降级

默认路径是本地 PixiJS 的 WebGL 保留场景。页面从 `/static/pixi.min.js` 加载随仓库提供的 `pixi.min.js`，不使用 CDN；随后 `tactical-map.js` 创建 `PIXI.Application`，关闭自动 ticker，交由地图的按需调度器驱动。

| 阶段 | PixiJS WebGL 主路径 | Canvas 2D 按需降级 |
| --- | --- | --- |
| 初始化 | WebGL 可用时创建 Pixi 应用、世界容器、图形层、实体容器与固定数量的雷达对象。 | Pixi 不存在、WebGL 不可用或初始化失败时创建单个 `canvas` 和 2D context。 |
| 绘制 | 对变化的层清除并重绘；可见实体保留对应 DisplayObject，离屏或消失时销毁。 | 在同一帧按相同顺序立即绘制可见内容。 |
| 异常恢复 | 监听 `webglcontextlost`；恢复成功后全量失效重绘。恢复超时或绘制异常则释放 Pixi 资源并切换 Canvas。 | 2D context 不可用或绘制失败时仅显示地图不可用提示，不影响指挥中心其余受限操作。 |
| 一致性 | 图形、颜色、相机、雷达、选中、目标预览与交互语义共用同一份模型。 | 保持与主路径相同的可读信息，而非另行实现功能分支。 |

Canvas 仅是按需、可用性优先的降级路径，不是第二个持续刷新渲染器。两条路径都会在尺寸变化时重设画布，设备像素比最高取 1.5，以控制像素填充量。

### 3.2 脏标记与绘制顺序

渲染器用 `DATA`、`CAMERA`、`SELECTION`、`LAYERS`、`ANIMATION` 和 `RESIZE` 脏标记合并同一浏览器帧内的更新。Pixi 路径中，只有受影响的层重绘；实体显示对象随可见域同步，不为完整世界创建对象。

```text
脱敏 dashboard 视图
        │
        ▼
实体归一化、别名合并、动画模型与相机
        │
        ▼
背景/观测 → 网格 → 地形资源/障碍/Beacon → 视野/路径 → 实体 → 边缘雷达
        │
        ▼
PixiJS WebGL（主）或 Canvas 2D（降级）
```

## 4. 视口与相机策略

地图采用局部视口，不尝试把已知世界完整缩放到一个画布中。这样远距离坐标或稀疏观测不会把核心附近的格子压缩到不可辨认的比例尺；操作重点始终是当前 Core、选中单位和附近态势。

| 项目 | 策略 |
| --- | --- |
| 初始锚点 | 首次收到地图数据时优先 Core，其次首个己方、首个敌方，最后为 `(0, 0)`；初始 scale 为 24。 |
| 坐标变换 | 由锚点、像素平移和 scale 把格坐标映射到视口中心；平移不改变世界或扩大可见世界。 |
| 缩放 | 鼠标滚轮围绕指针缩放，工具栏和键盘也可缩放；scale 严格限制为 **8–56**。 |
| 聚焦与跟随 | 选择实体可聚焦到其位置并至少放大至 24；跟随的实体在新帧以其目标位置更新锚点。拖拽、方向键和聚焦坐标会解除实体跟随。 |
| 复位与持久化 | 复位回己方 Core（无 Core 时原点）和 scale 24；锚点、平移、scale、跟随对象及图层偏好以 `localStorage` 保存，存储不可用时静默退化。 |
| 坐标辅助 | 自适应标尺每轴至多 16 个标签，标签间至少约 64 像素；中央准星与坐标条显示中心、选中和目标格。 |

远端对象不应迫使相机缩小。对视口外的敌方、资源与 Beacon，地图按距离优先选取最多 10 个，放置在画布边缘的方向箭头，并标注类型与格距。这提供导航线索，同时保留局部格子的可操作尺度。

## 5. 图层、符号与配色

基础颜色与指挥中心一致，便于在桌面与移动布局中保持识别连续性。

| 图层/语义 | 颜色 | 用途 |
| --- | --- | --- |
| `bg` 背景与迷雾 | `#071016` | 未观测区域的深色底。 |
| `observed` 已观测区域 | `#10232C` | 当前已观测格；连续同一行格先压缩为线段再绘制。 |
| `grid` 网格与地形描边 | `#31515E` | 近距离显示每格，较远时按 2 或 5 格抽样；五格主线更醒目。 |
| `friendly` 己方与 Beacon | `#58C9BE` | Worker 方形、Vanguard 三角、Ranger 菱形；Beacon 使用圆环。 |
| `resource` 资源与己方 Core | `#D9AA55` | 资源用菱形；Core 用圆形并与普通己方区分。 |
| `enemy` 敌方与生命条底色 | `#E56B73` | 当前可见敌方、受损生命条底色和错误提示。 |
| `obstacle` 障碍 | `#263B45` | 带网格描边的实心方块。 |

选中实体以浅色环和十字标识；受阻实体降低透明度。标签默认只对选中、悬停或足够放大（scale ≥ 30）的实体显示，避免小比例尺文字遮挡。视野层可关闭，或切换为“Core 与选中对象”及“全部己方对象”；迷雾、坐标和标签也可独立开关。

## 6. 交互与任务边界

| 操作 | 行为 |
| --- | --- |
| 平移 | 左键拖拽或方向键移动视口；拖动超过阈值后不触发点击选择。 |
| 缩放 | 滚轮围绕指针缩放；`+`/`-` 与工具栏按钮围绕视口中心缩放，仍受 8–56 限制。 |
| 选择 | 点击或双击最近实体；友方选择同步指挥中心单位列表，地图可由列表反向选择或聚焦。 |
| 坐标聚焦 | 资源列表可将地图中心移到该格；悬停持续更新光标格坐标。 |
| 目标选择 | 开启“从地图选点”后移动仅预览格，点击锁定格并预填受限 `MOVE_TO_CELL` 任务；`Esc` 取消。地图只负责选点，真正排队仍要经过会话、CSRF、版本和下一 Tick 的命令校验。 |

地图不会直接调用 SDK controller，也不会从回放画面生成即时游戏动作。它和命令 API 之间只通过已限制的 UI 字段连接，因此点击历史地图同样不改变该历史帧或绕过当前权威 Tick。

## 7. 性能与可用性约束

| 约束 | 实现方式 |
| --- | --- |
| 帧率上限 | 脏调度器以 `requestAnimationFrame` 合并更新，并限制为最多 **30 FPS**；没有脏标记或动画时不绘制。 |
| 移动观感 | 相邻快照位置变化使用 180ms 三次缓出插值；用户偏好减少动态效果时直接跳到新位置。 |
| 观测格 | 最多 2,000 格，按行压缩成连续段，避免每格一个 Pixi 图形或 Canvas 绘制调用。 |
| 可见对象 | 地形和实体按相机 bounds 裁剪；Pixi 只为当前可见实体保留 DisplayObject，离屏即释放。 |
| 雷达与标尺 | 雷达池固定 10 个；坐标标签每轴固定池 16 个，避免交互时反复创建 DOM/图形对象。 |
| 后台页面 | 页面不可见时取消地图调度和 dashboard 轮询；恢复可见后重设尺寸并全量刷新。 |
| 诊断 | `?debugMap=1` 显示渲染器、FPS、帧耗时、对象数、坐标标签、迷雾段与失效原因，正常模式不展示。 |

这些限制优先保证指挥中心可用。地图渲染异常只显示局部错误状态，不能阻塞服务状态、受限任务表单或 Agent 的独立 Tick 提交。

## 8. 当前态势与回放器的分离

回放器是指挥中心的只读时间导航，不是地图的另一份状态模型。Dashboard 保留最近至多 32 帧脱敏快照；滑块、标记和 700ms 播放器选择其中一帧，再由同一个 `renderTacticalMap(view)` 渲染该帧。

| 模式 | 地图显示 | 后台行为 |
| --- | --- | --- |
| 实时态势 | 最新帧，标记为“实时态势”。 | 每 3 秒刷新 dashboard；新帧到达后继续跟随最新 Tick。 |
| 历史回放 | 用户选择的历史帧，标记为“历史回放”。 | 当前态势仍在后台刷新；回放索引尽量保留同一 Tick，历史帧被滚动窗口淘汰时才收敛到可用范围。 |

因此，“历史回放”只改变观察对象，不能把旧帧解释为当前世界，更不能恢复旧 controller、状态文件内容或旧行动计划。地图对两种模式使用相同的脱敏投影、相机和渲染限制，确保回放不会成为额外的数据泄露或性能路径。

## 9. 验证要点

前端单元测试覆盖 scale 边界、稀疏坐标尺、观测格压缩、别名对齐、相机可见边界、重复回放切换的实体回收，以及 30 FPS 脏调度/180ms 动画的合并行为。服务测试还覆盖本地静态资源和 dashboard 投影的可用性。

验证地图时应同时确认以下边界：WebGL 不可用时 Canvas 2D 仍能显示；上下文丢失后不出现持续重绘；地图只接收 allowlist 投影；历史回放不会冒充当前态势；以及渲染故障不会影响下一 Tick 的策略与提交流程。
